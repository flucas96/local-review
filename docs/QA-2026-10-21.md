## 0.4.6 notification queue fix

The same native check exposed a separate issue: **Standarddarstellung wiederherstellen** stayed queued behind the still-open enhancement notification. The installed VS Code message service resolves notification promises only when the notification closes or an action is selected. Appearance commands awaited these promises inside their serialized mutation queue. They now keep settings and backup operations awaited but do not wait for informational or error notifications to close.

Strict TypeScript checking and **185 tests pass**, including regressions that leave success, high-contrast and error notifications unresolved while subsequent appearance commands complete. The first restricted test run could not open local test ports; the authorized loopback-enabled run passed all tests. Native apply and focus/blur are verified above. The corrected native reset/reapply sequence and activation of 0.4.6 remain pending: later computer-control attempts returned no available VS Code window. The current project's enhanced colors remain applied. A new authenticated Claude roundtrip was not part of this appearance check.
