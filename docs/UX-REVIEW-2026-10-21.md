## 0.4.8 · choose the Claude conversation

The default connection choice now opens Claude's specific-conversation picker with `--resume`; **Neue Unterhaltung** starts fresh. **Review → … → Verbindungsbefehl kopieren** provides the same choices for a separate local terminal. Copying includes the project directory and private review settings, without launching or closing a process. Existing running conversations must exit before resuming; true in-place attachment is not shipped.

Managed sessions offer **Terminal anzeigen** and explicit **Unterhaltung wechseln**. Cancelling either picker or failing preparation leaves the existing terminal intact. An active receiver without a live managed terminal blocks a competing launch. Ended terminal identities cannot be rediscovered as live owners, and readiness is checked again after awaited selection and preparation. This is a conservative launcher guard, not exact session-bound authorization for every MCP update.

## 0.4.7 · review ergonomics

Scope: optimize the extension; use a separate local copy of Review Lab as the test project. The dashboard was not redesigned. Three parallel reviews covered native conversations, the composer/PR handoff, and connection recovery; a separate cross-review found no actionable regression.

## What changed

- Native conversations reuse existing comment objects during progress updates; unchanged replies and their navigation actions are not recreated.
- Command-created drafts preserve the source context captured when opened. Changed or ambiguous code is shown as a saved excerpt; uniquely moved code follows a confirmed match. Native gutter-created drafts still capture at submission because VS Code exposes no draft-creation event.
- Code selection uses a soft surface and a left accent instead of a box around every line. The Review toolbar exposes the contrast action directly, and list entries include filename:line.
- **Review → … → Zentrierte Ansicht** offers a narrower native layout. It toggles VS Code's centered editor, narrowing source and inline comments together without changing saved settings. Side-by-side diffs retain VS Code's automatic wider layout.
- Composer input defers slash interpretation during IME composition. A new empty `/r` explains that a conversation is needed.
- Edited and failed PR handoffs can be resumed after closing, within the same editor session. The snapshot is preserved; a fresh snapshot is a separate choice. New edits clear the published state, and unchanged published text cannot be sent again.
- Reloaded or late-restored managed terminals are reused. Cancelled/failed replacement preserves the existing terminal. Private connection files are replaced atomically with mode `0600`.
- Tool connectivity and automatic feedback reception have separate states. An absent receiver shows **Zustellung pausiert** and offers reconnection; only an explicit event acknowledgment changes delivery status.

## Remaining limits and follow-up

- Exact focus of a programmatically created native draft is behind VS Code's proposed `commentReveal` API. Its public generic focus command can select another provider's thread, so it is not invoked automatically. Click the field, or use the native gutter plus.
- PR draft recovery lasts until the extension host reloads. PR publication still needs a signed-in GitHub CLI and a real open PR. The new browser checks do not establish a real remote publication.
- The prior real headless Claude ask/implement/summarize roundtrip remains valid historical evidence. The 0.4.8 run above verifies authenticated idle delivery after resume; busy-agent delivery and terminal restoration after a full VS Code restart still need a dedicated live run.
- Unread reply navigation, a direct Claude-to-thread action, an external-terminal attach flow and stable review baselines remain tracked in [daily-workflow issue #4](https://github.com/flucas96/local-review/issues/4). These were not represented as completed by this release.
